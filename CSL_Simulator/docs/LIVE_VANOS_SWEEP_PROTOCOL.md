# Live VANOS Sweep Protocol — 実車でカム→空気の伝達関数を測る (Stage 121)

**目的**: 谷帯 WOT で吸気/排気カム角をライブ指令し、**λ積分器の応答**から「カム位相→実新気量」の
伝達関数を実測する。これは (a) 谷が「回復可能なヘッドルーム」か「本質的ガス力学」かの判定、
(b) シム(S120)の差分予測の検証、(c) そのまま Stage 2(車を超える VANOS)の探索、を兼ねる。

**実施はオーナー**（走行＋ツール操作）。本書は仕様と安全境界。解析は `scripts/analyze_vanos_sweep.py`。

> ⚠ この経路は**保護リミッタを丸ごとバイパスする**。`K_EVAN1_SOLL_MIN/MAX`・`KL_EVAN_SOLL_BEGR`
> は効かず、唯一のクランプは受理判定の −20/+80 のみ。範囲制限は**自分でかける**。
> お車は `rf_korr`(EGT 由来の増量保護)がゼロ化済み＝**EGT 自動保護は無い**。EGT の手動監視が唯一の保護。

## 0. なぜ λ積分器を見るのか（rf/ml ではない）

この CSL は純アルファN(`k_rf_hfm_cfg=0`)。`RF = kf_rf_soll(N, スロットル)×補正` で、**カムを動かしても
`rf`/`ml` は動かない**（再チューンするまで）。実空気が増えれば閉ループが燃料を足すので、反応するのは
**λ積分器 `la_f_regler`**:

```
カムが良くなる → 同一モデル RF に対し実空気が増える → 希薄化
              → 閉ループが燃料を足す → la_f_regler が上がる
∴ ある運転点での最大 VE ＝ λ積分器の要求が最大になるカム角
```

VANOS マップの軸は `(n, aq_rel)` で `rf` ではないので、**カムを振っても運転セルが移動しない（正帰還なし）**。
VE が完璧でなくても、同一セル内でカム角だけ振れば VE 誤差は定数オフセットとして相殺される。

**Stage 119 の含意**: BMW 自身の残留ガスモデルは谷を内部EGRで説明できない(残留差 +1.3pp vs VE 42pp)。
∴ カムの効き筋は**EGR 低減ではなく IVC(吸気弁閉)/掃気による新気誘導**。回復が起きるなら λ積分器は
「オーバーラップ最適点」ではなく「IVC 最適点」で最大化するはず。
**Stage 120 の予測（事前登録）**: シムは cam に**低権限**しか与えない — 全カム格子で VE レンジ 8.1pp
（実車の谷→峰 56pp に対し平坦 ~103）、dVE/d(吸気 live) = **−0.135**@3100（吸気進角はむしろ VE 微減、
純正フル遅角が最大付近）、排気はほぼ平坦。∴「実車で吸気進角が空気を増やすか・減らすか（符号）」と
「権限の大きさ」の両方が sim↔car の直接判別項目。

## 1. コマンド（逆アセンブルで確定 — `CSL_0401_Binary_Disassembly_Notes/docs/vanos_ds2_target_override.md`）

```
DS2 frame:  12 07 0C <pin> <angle> 00 <XOR>
  0x12 = DME, 0x07 = length, 0x0C = "Steuern"(アクチュエータ制御)
  pin 0x07 = 吸気バンク1 VANOS 目標
  pin 0x0A = 排気バンク1 VANOS 目標
  angle    = 符号付きバイト、1 °KW 刻み、範囲 −20 … +80 °KW（内部 ×10 = 0.1°KW）
  period   = 0x00（この経路では未使用）
  応答 payload[1]: 0=受理 / 2=>+80 / 3=<−20 / 4=作動条件未成立
```

- 受理条件は `ZUSTAND_MOTOR & 0x1C`(LL|TL|VL＝エンジン稼働、**走行中含む**) と
  `EVAN1_ST` bit3(VANOS 油圧レディネス)の**2つだけ**。車速・回転数判定なし。
- 保持は DS2 セッション(`b_diag`)依存。**キープアライブ `0x9E` を数秒毎に送る**。
  止めれば次のバックグラウンド周期でマップ制御へ自動復帰＝**中断手順（フェイルセーフ）**。
- **符号規約はライブ/DS2 では素の °KW**（マップ表示の 70+/128− エンコードとは別）。指令バイト = 実カム角。
- 排気の受理は**吸気バンクのレディネス**に依存（設計上の結合）。

### 保存可能域と対応（表示↔ライブ↔指令）

| | ライブ `*_ist`(°KW) | マップ表示 | DS2 指令バイト |
|---|---|---|---|
| 吸気 | 0 … 60（進角+） | 70 … 130 (=live+70) | 0 … 60 |
| 排気 | 0 … 45 | 128 … 83 (=128−live) | 0 … 45 |

**書き戻せる最適点にするため、探索窓は保存可能域(吸気0-60/排気0-45)に閉じ込める。**

## 2. 前提条件（ほぼツールの PATCH がそのまま満たす）

| 項目 | 値 | 理由 |
|---|---|---|
| `k_rf_cfg` | 0x12 → **0x02** | MAP 積分 off。切らないと `rf_p_saug_i` が改善分を黙って吸う |
| `K_LAA_TMOT_MIN` | 69 → **100 °C** ＋ RESET ADAPT | LTFT 凍結（学習が測定を汚さない） |
| `KF_BZ_WDK_VL` | → **102.3 %** | 全開でも λ閉ループ維持（VL に入れない）＝λ積分器が生き続ける |
| VANOS 学習 | クリア | 学習中(`VAN_ADAP_ST` bit4/5)は指令が受理されない |
| 水温 / 油温 | ≥75 / ≥40 °C | 油圧レディネス成立の条件 |
| EGT 上限 | **先に決める** | rf_korr ゼロ化済み＝自動保護なし。手動監視が唯一の保護 |

## 3. ログチャンネル（DS2 `0x0B <selection>`、物理値 = add + raw*scale）

| 用途 | ブロック | offset | scale |
|---|---|---|---|
| **λ積分器 b1/b2**（主観測量） | 19 | 40 / 42 | 1/32768 |
| 点火角 気筒別 `tz1..6`（ノック監視） | 19 | 22–32 | 0.1 °KW |
| 噴射時間 気筒別 `ti1..6`（裏取り） | 19 | 6–16 | 0.001 ms |
| **吸気カム 実/目標** `evan1_ist/soll` | 35 | 2 / 4 | 0.1 °KW |
| **排気カム 実/目標** `avan1_ist/soll` | 35 | 6 / 8 | 0.1 °KW |
| MAP `psau_local`（唯一の実測圧） | 35 | 22 | 1/32 mbar |
| rpm `n` | 3 | 0 | 1 |
| 空気量 `ml`（動かない＝アルファN の確認用） | 3 | 4 | 0.25 kg/h |
| 負荷 `rf`（同上） | 3 | 8 | 0.1 % |
| スロットル `aq_rel`/`wdk1`（WOT/VL 判定） | 3 | 20 / 27 | 100/32768 / 0.1% |
| EGT `tabg`（保護監視） | 3 | 14 | 16 °C（粗い） |
| 水温/油温 | 3 | 11 / 12 | 1 °C, −48 |

- **必須ブロック = {3, 19, 35}**（≈3.0 Hz）。Web版ロガーは {3,19} のみなので **block 35 を足すか C# 版カタログを使う**。
- 定常保持なら 3 Hz で害はない。過渡(WOTプル)はサンプル不足に注意（§5）。

## 4. 指示値の決定戦略（何を指令するか）

**純正セル近傍のアンカー付き一因子掃引**。探索最適化ではなく仮説判定用の格子。

| 系列 | 固定 | 掃引（指令 °KW、= ライブ角） | 根拠 |
|---|---|---|---|
| ベースライン A | — | **override なし**（純正スケジュール） | 4-5 プルごとに挟みドリフト補正 |
| 吸気系列 | 排気=純正 | **0 / 5 / 10 / 15 / 20** | 実走 WOT は吸気ほぼ無進角(0-14°)。進角の回復余地を跨ぐ |
| 排気系列 | 吸気=純正 | **30 / 35 / 41 / 45** | 谷帯純正 ≈41(3100)/35(2900) の周辺 |
| 組合せ | — | 応答最大の吸排 2-3 点 | 交互作用の確認 |

- ガード: 保存可能域内かつ純正セル ±15°。`tz` がベースライン比 >4° 遅角、または EGT 上限で**その設定は破棄**。
- 谷底 **3100 rpm を最優先**。次に 2900、余裕があれば 3300。峰 3900 は「谷の伝達関数」の対照。
- 高負荷・大進角の点は**最後**（点火・充填モデルはマップ上の cam を前提＝ノック領域に入りうる）。

## 5. 変更の頻度と方法・λ の取り方（3 段構え）

**定常 WOT 保持は路上で物理的に不可能**（平坦路で全開を吸収する負荷が無い）ため:

1. **経路検証（アイドル、5 分）**: `0C 07 <角度> 00` を 1 発 → 応答 payload[1]==0 と `evan1_ist` の
   追従で**経路と符号規約を実車確定**（逆アセ資料が自認する唯一の未追跡点＋符号を同時に潰す）。
2. **定常部分負荷ホールド（一定速巡航、15-20 s/点、数点）**: カムを ±5° ステップ →
   **λ積分器の時定数と限界サイクル σ を実測**（3 Hz×15 s ≈ 45 サンプル/点）。測定分解能を確定してから WOT へ。
3. **WOT A/B/A プル（本番）**: **4速推奨**（2500→4300 rpm ≈ 66→113 km/h、~4.4 s、~13 サンプル/プル@3Hz）。
   各設定 **3 プル** → 300 rpm ビンで 6-7 サンプル/ビン → λ振動 σ≈2% として SEM ≈ 0.8%。想定シグナル
   5-20% に十分。際どい設定のみ +2 プル。

**カム変更の作法**（override は `KF_*_DMAX` レート制限をバイパス＝ランプはこちらの責務）:
- **プル中はカム角固定**（1 プル = 1 設定）。これが λ 応答を設定間比較に落とす骨格。
- 設定変更は**プル間の低負荷巡航中**に: **1 コマンド ≤2°KW、~100-200 ms 間隔のランプ**
  （各ステップで payload[1]==0 と `evan1_ist` 追従を確認、偏差 <10° 維持で DTC 回避）。15° 移動 ≈ 8 ステップ。
- 有効サンプル条件: `ist−soll` ≤2°（両バンク）・ペダル≥99・分析帯 **2700 rpm 〜**（進入 2500、
  初期 0.5 s は過渡増量と `KL_DYN_TZ_DBGR` 遅角で汚染するため破棄）。
- 4速へは **60 km/h 以上でシフトイン**（騒音トルクキャップ `KL_MD_BEGR_NOISE` 武装窓 46-54 km/h を回避。
  空気測定自体は汚しにくいが、トルク/点火の介入区間を分析から外すため）。

総量 ≈ 10 設定 + ベースライン挟み込み ≈ **45-50 プル ≈ 40 分 × 2 セッション**。

⚡**プル数の実測補正（Stage 121、掃引エンジンのテストで判明）**: 1 プル 13 サンプルを 300rpm ビンに
配ると **1 ビンあたり 1〜3 サンプル**にしかならない（2500rpm 進入・140rpm/サンプルの実分布で
3000/3300/3600/3900/4200 に 1/2/2/3/1）。証拠ゲート `minSamples=6` に対し:

| プル数/設定 | 判定が成立するビン |
|---|---|
| 3 | 3900 のみ（帯端はもちろん 3300/3600 も不足しがち） |
| **4** | **3300 / 3600 / 3900**（谷帯の本命が揃う） |
| 5-6 | 上記＋ 3000 / 4200 の帯端 |

∴ **各設定 4 プルを最低ラインとする**。谷底 3100rpm を含む 3000 ビンまで欲しい場合は 6 プル。
カバレッジ盤が「あと何回のプルが必要か」を出すので、走行中はそれに従えばよい。

## 6. 安全設計（重要度順）

1. **リミッタ全外れ**。回転数・負荷に応じた探索窓を自分でかける。保存可能域を超えない。
2. **点火・充填モデルはマップ上の cam 前提** → 大進角×高負荷はノック領域。EGT と `tz`(遅角)を見ながら狭く。
3. **偏差 `EVAN1_XD`/`AVAN1_XD` > 10 °KW で VANOS DTC**。ステップではなくランプ、`ist` 追従を待つ。到達不能角度を投げない。
4. **学習中は受理されない**。開始前に VANOS 学習をクリア。
5. **排気は吸気レディネス依存**。排気だけ振る場合も吸気側 `EVAN1_ST` bit3 を確認。
6. **中断＝キープアライブ `0x9E` 停止**（次周期でマップ復帰）。緊急時はセッション切断。
7. WOT プル中は**ドライバーが画面操作しない**（§UI）。
8. EGT 上限に達したらその設定を破棄（rf_korr ゼロ化＝自動保護なし）。

## 7. 計測 UI（実装済み・デプロイ済み）

**スマホで開く URL**: `https://csl-sim-m.pages.dev` → 「Live (DS2)」→「VANOS 掃引」

- **接続**: Android Chrome は WebUSB（FTDI ケーブル）、PC は Web Serial。自動判別し画面に接続方式を表示。
  実機が無くても「モック」で全操作（指令・到達・カバレッジ・アップロード）を確認できる。
- **安全表示**: 画面最上部に**排気温度**を常時表示（880°C 警告 / 940°C 中止）。この車は `rf_korr` を
  ゼロ化しており DME 側の自動増量保護が無いため、**この表示が唯一の保護**。
- **カム指令**: 軸（吸気/排気）を選び角度ボタンを押すと、**2°KW 刻みのランプ → 到達待ち → 「到達。全開プルを
  開始してください」**まで自動。指令できるのは書き戻せる範囲のみ（吸気0-60 / 排気0-45）。
  **中止**ボタン（またはタブを閉じる・切断）でキープアライブが止まり、DME のマップ制御へ自動復帰。
- **カバレッジ盤**: 横=rpm ビン × 縦=カム設定。色は**証拠の量**（λ の値ではない）。
  「次にやること」が残り必要プル数を、「除外されたサンプル」が理由別内訳を出す。
- **アップロード**: 「サーバーへ送信」で収集器 Worker へ。初回のみ「設定」でトークンを入力（端末に保存）。
  同じ記録を再送しても**重複しない**（id で upsert）。
- **記録の保全**: サンプルは 5 秒毎に IndexedDB へ追記される。ブラウザが落ちても次回起動時に
  「前回の記録が N サンプル残っています」と復元を提案する。**メインタブを切り替えても接続・記録は切れない**。

### 実装メモ（元の UI 仕様）

- **2 モード**: (a) 定常ホールド＝アーム→大きなカウントダウン→"HOLD" リング蓄積、λ整定・`ist`追従・
  rpmドリフト小の全条件が揃った区間のみ計上、外れは灰色で無効可視化。(b) WOT プル＝プル前アーム→
  プル全体を自動キャプチャ→過渡・`ist≠soll`・ペダル<99 をライブ棄却（transient rejection filter）。
- **カバレッジ盤**: 横=rpm ビン(300刻み) × 縦=カム設定、色は**信頼度(SEM)/有効サンプル数**（λ値ではない）。
  λ応答は別パネル。A/B/A ベースラインは対の列で可視化しドリフトを目視。
- **安全運用（最重要）**: WOT プル中はドライバーが画面操作しない。パッセンジャー・オペレーター、または
  アーム&自動＋**音声コールアウト**（valid / bin完了 / abort）。判定はオフライン、ライブ盤はカバレッジ確認専用。

## 8. 取得データ形式（`analyze_vanos_sweep.py` が読む CSV）

C# ツールの CSV（ブロック毎 1 行、他ブロック列は null、時間軸 `elapsedMilliseconds`）を前方補完した
**ワイド CSV** を想定。必須列（別名は解析側で吸収）:

```
t_ms, rpm, evan1_ist, avan1_ist, evan1_soll, avan1_soll,
la_f_regler1, la_f_regler2, ml, rf, psau_local, tz1..tz6, tabg, pedal, wdk1,
cmd_intake, cmd_exhaust        # そのプルで指令していたカム角（設定ラベル。無ければ soll から復元）
```

- `cmd_intake`/`cmd_exhaust` が無い場合は `evan1_soll`/`avan1_soll` を設定ラベルとして使う。
- ベースライン(override なし)行は `cmd_* = "base"` か空。
- ⚡**block 3 を間引く場合の必須条件**: 解析器は `pedal`（無ければ `wdk1`）を**直前の block-3 読みから
  前方補完**して WOT 判定する（4 秒以上古い＝stale は棄却）。したがって **block 3 は最低 4 秒に 1 回**は
  ポーリングすること。全く無いと全サンプルが「スロットル不明」として棄却される（安全側に倒す設計）。

## 9. 判定ゲート（実験後）

| 実車の応答 | 帰結 |
|---|---|
| 谷帯でカムにより λ積分器（=実空気）が大きく動く | 谷は主にカムスケジュール由来＝**回復可能ヘッドルーム**。Stage 2 は実機 STEP 2 手順でそのまま進む。シムの欠陥は「カム感度過小＋進角で破綻」に特定 |
| ほぼ動かない | 谷は**本質的ガス力学（箱モード）**＝道C完了。Stage 2 は実機ライブ探索で進行、シム物理は道A対象のまま |
| **吸気進角で λ が微減（シム予測どおりの符号）** | シムの cam→空気の**符号**は正しく権限だけが問題、と切り分けが進む。純正フル遅角＝最適の確認 |

どちらでも: 実測伝達関数＝道(B)の「測定伝達要素」としてシム検証の新基準になる。

## 10. アップロード → 回収（Cloudflare 収集器、Tuner とは別デプロイ・別 D1）

- 収集器: `CSL_Simulator/vanos-collector/`（独立 Worker `vanos-sweep-collector` + D1 `vanos-sweeps`、
  Bearer トークンは Tuner のとは別発行）。デプロイ手順は同ディレクトリ README。
- ロガー組込み: `vanos-collector/client-snippet.ts` の `uploadSweep()` を掃引レコーディング終了フックへ
  （gzip(JSON)→base64→`POST /sweeps`、best-effort・失敗してもローカル記録は失わない）。
- 回収・解析（このリポジトリから）:
  ```
  python backend/scripts/fetch_sweep.py --list
  python backend/scripts/fetch_sweep.py <id> --analyze        # CSV 保存 → analyze_vanos_sweep.py
  ```
  URL/トークンは env `VANOS_COLLECTOR_URL` / `VANOS_COLLECTOR_TOKEN`（または --url/--token）。
- 往復健全性は検証済み: 合成掃引(頂点+12) を ingest → CSV 回収 → 解析器が +12.4 を復元（E2E PASS）。
