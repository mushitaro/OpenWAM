# 従来モデルと修正モデルの選択

**後続更新:** Builder条件からの入力生成・評価を実装した。現在の画面と任意RPM/RO/形状の対応は [CORRECTED_BUILDER_VE_2026-11-11.md](CORRECTED_BUILDER_VE_2026-11-11.md) を参照。以下は初版の登録ケース接続の履歴であり、「一般化は対象外」という記述は初版の範囲を示す。

## 実装・検証計画

従来OpenWAMを既定に保つ。修正モデルは2026-10-27の時計差修正済み有限体積ソルバーを独立C++ターゲットとして保存し、モデル固有の入力・結果・実行ファイルを分離する。2つの検証枝は変更しない。

修正モデルは任意のWAMデッキを受け取る置換exeではない。現在の試験実装は3900 rpm、固定6気筒形状、指定の管網・弁駆動と完全checkpointに対応する。登録済みケースの条件を画面に表示し、Builderの別条件を適用したかのように扱わない。任意RPM/RO/形状への一般化は本接続の対象外であり、20セル実車精度達成とは区別する。

追加の長時間計算は実行しない。短区間を旧試験exeと新ビルドで比較し、保存状態の一致、モデル切替、保存読戻し、入力改変拒否、タイムアウト/中断を確認する。1周期評価の実行経路は実装するが今回起動しない。

修正モデルのVEはIVC酸素換算空気量を指定の参照空気質量で除した値。旧モデルの総捕捉量/ECU RFと無条件に同一視しない。区間中にIVCを通過していない気筒は以前の保存値と明示し、6気筒の新しい評価が完了したとはしない。strict周期/格子未達、実車精度未証明を維持する。

## 操作と保存

Simulation画面の「計算モデル」は起動時に従来モデル。修正モデルを選ぶと専用ケース選択と6気筒の酸素換算VE表示へ切り替わる。従来のマップ/最適化結果は混ぜて表示しない。

- 短区間動作確認: 10 native frames、上限60秒。IVC未更新なら以前の値と表示。
- 1周期VE再評価: 登録seedから720度、上限4時間。全6気筒のIVC更新を判定する。今回の実装検証ではこの長時間計算は起動していない。
- 前回結果: 修正モデル専用のlast.jsonから読戻し。計算失敗は過去の成功結果を上書きしない。
- 中断: 子ソルバーを終了・回収し、失敗/中断記録を保存する。完了扱いしない。

修正モデルは `build/corrected_ve_evaluations/<run_id>` に入力snapshot・要求・終了状態・CSV・結果を保存する。原入力の隣へdecodeファイルを書かず、snapshotだけを読む。入力SHA、モデルexe/検査exe SHA、参照空気量、開始/終了時刻、気筒別IVC更新、経過時間、保存収支を記録する。従来キャッシュは共用せず、修正モデルは毎回新しい出力先を使う。APIは未知モデル・未登録ケース・未対応条件・過大時間上限を拒否し、従来ソルバーへ暗黙fallbackしない。

## ビルドとケース登録（Windows x64 / MSVC）

```powershell
cmake -S Source/CorrectedVE -B build/corrected_ve
cmake --build build/corrected_ve --config Release --parallel 4
python CSL_Simulator/backend/scripts/register_corrected_case.py <既存C-cycleルート> <完全周期終端checkpoint> --id <一意ID> --label <条件名> --reference-mass-kg <参照kg> --reference-definition <定義>
```

大容量の駆動入力/履歴はGitへ重複登録しない。cases.jsonに外部原本の場所とSHAを保持する。別PCでは既存アーカイブから必要入力を復元し登録する。既存IDの内容変更は拒否される。checkpointは試験時のWindows x64バイナリ形式であり、異なるABIへ無検証で移植しない。

今回登録した `ccycle113` は半CFL比較のbaseline周期113終端、3900rpm、固定管網/弁駆動。RO値は未同定。参照質量640.77mgを明示した旧標準空気基準であり、ECU RF基準との一致を主張しない。1周期処理の費用は過去の基準周期で約74分の実績があるが、本接続の長時間実測ではなく終了保証ではない。

## 実結果

- コピーした数値ソース29ファイルを旧診断manifestのSHAと全件照合。`Source/CorrectedVE/provenance.json`参照。数値本体の変更なし。新規CMakeとcheckpoint検査exeを追加。
- Releaseビルド成功。既存試験exeと新ビルドを同一seedから約25µs進め、終端全バイト一致。終端SHA `71cb9fc8e8afe8fffa78e4dca7d080464b732bf99274536cc210d79c90d6045d`。
- 新経路4.28秒、旧exe比較4.11秒（読込み等の計測範囲が異なるため速度比較には使わない）。保存収支最大1.4195e-10で既存2e-8以内。旧exeとの同一性確認であり、全履歴独立再監査ではない。
- 実C++を呼ぶAPI短区間・保存読戻し、入力SHA改変拒否、未知モデル/条件拒否、二重起動拒否、実子プロセスのタイムアウト/中断後不在を確認。
- ブラウザーで従来既定→修正→結果表示/読戻し→従来への復帰を確認。UI試験のHTTP応答は実短区間結果の再生であり、追加のソルバー計算ではない。画面目視済み。
- 既存npm test、test:capture、TypeScript型検査、portedソース照合、backend収録契約テスト成功。ECU操作なし。

## 残る機能と科学的制限

これは修正モデルを本体から実行・保存できる接続であり、任意条件のVEマップ生成への汎用化ではない。RPM/RO/形状から修正モデル用の管網、弁駆動、初期状態を生成する変換と検証が別途必要。従来モデルとの差分比較にも同じ条件と指標を揃える必要がある。修正有限体積モデルの20セル実車精度確認は未達のまま。検証2枝・旧履歴・元固定ファイルは変更しない。

取り込み元masterにはClaudeによる `8b35f62` のhealthy-stackモデル29セル採点が既にある。RO1〜10・1800〜2900rpmの採点と、18セルの過充填/11セルのNaN失敗は `VE_ACCURACY_20_CELLS_2026-11-10.md` を優先する。「全モデルについて確認0セル」という古い記述へ戻さない。この29セル採点、早期NaN打切り設定、既存スクリプトはそのまま保持して統合した。29セル採点は今回接続した修正有限体積モデルの評価ではなく、RO1〜100全範囲も未達である。
